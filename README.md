# BioLink — карточка белка из трёх научных баз одним запросом

Маленькая веб-программа на Python (Streamlit). Вводишь название гена или
белка — например `insulin`, `TP53` или `p53` — или готовый код UniProt,
например `P01308`. Программа сама опрашивает три открытые научные базы:

- **UniProt** — что это за белок, какая у него функция, какой организм,
  какая последовательность аминокислот;
- **NCBI Gene** — данные про ген: на какой хромосоме лежит, официальное
  описание, другие названия;
- **RCSB PDB** — есть ли для белка расшифрованная 3D-структура (метод,
  разрешение, ссылки), плюс **интерактивная 3D-модель, которую можно
  крутить мышкой прямо в браузере** (движок 3Dmol.js через py3Dmol).

Найденное склеивается в одну карточку: в браузере, в текстовом файле и в
JSON. Идея — «связывающий слой» между базами (как Palantir, но для
биологии): вместо того чтобы вручную открывать три сайта и переписывать
данные, человек делает один запрос.

## Два режима

### 1. Поиск карточки

Один запрос → карточка с блоками по каждой базе, метриками и шкалой
уверенности сопоставления.

**Как сайт работает при неоднозначном запросе:** если по имени (например
`p53` или `HER2`) в UniProt несколько похожих белков, сайт НЕ берёт первую
запись молча — он показывает список найденного (код, название, организм),
и карточка собирается только после выбора пользователя. Точный код UniProt
(`P01308`) показывает карточку сразу. Организм пишется бытовым названием,
а научное (латинское, курсивом) — в скобках: «Человек (*Homo sapiens*)».

**Шкала уверенности** — центральная фишка проекта: карточка честно
сообщает, *как именно* запись была сопоставлена с запросом:

| Способ сопоставления | Уверенность |
|---|---|
| введён точный код UniProt | высокая |
| запрос совпал с основным именем гена | высокая |
| запрос — синоним гена | средняя |
| обычный текстовый поиск | низкая |

Если запрос неоднозначный и запись выбрана из списка вручную, уровень
определяется способом поиска как обычно, но карточка отдельно помечает:
«выбор записи подтверждён вручную». Ручной выбор — отдельный факт, а не
уровень шкалы: кандидатов больше одного почти всегда, и если бы выбор
человека засчитывался как «высокая», почти любой поиск получал бы зелёную
плашку — и шкала переставала бы что-либо означать.

### 2. Массовая обработка

Вставь список названий (через запятую, с новой строки или файлом
`.txt`/`.csv`) — программа по очереди соберёт карточки и выдаст таблицу:
найденный код, организм, число структур, уровень уверенности, примечание.
Результат скачивается в CSV (UTF-8 с BOM — открывается в Excel без
кракозябр). Прогресс виден по ходу: сколько обработано, сколько осталось;
прервать прогон можно в любой момент — обработанные строки сохранятся.

**Честное предупреждение:** в массовом режиме программа не спрашивает по
каждому названию, как вкладка «Поиск», — если записей несколько, берётся
первая по приоритету. Спорные случаи (совпадение по синониму или обычным
текстовым поиском) помечаются «неоднозначно» и попадают в счётчик сводки.
Когда же программа просто выбрала человека среди организмов с тем же
именем гена (TP53 есть и у крысы, и у мыши), в «примечании» стоит
спокойная пометка — это нормальная работа приоритета, а не риск. Это тот
же подход, что у больших инструментов аннотации (например, `--pick` /
`--flag_pick` в Ensembl VEP): автоматический выбор по прозрачным правилам
плюс явная пометка спорных строк.

## Как запустить

```bash
pip install -r requirements.txt      # streamlit, requests, pandas, py3Dmol
streamlit run app.py
```

Браузер сам откроется на `http://localhost:8501`.

**На телефоне (в том же Wi-Fi):** узнай IP компьютера (Windows: `ipconfig`,
строка «IPv4-адрес») и открой `http://<IP>:8501`. При первом запуске
Windows спросит про брандмауэр — разреши доступ для частных сетей.

**Через интернет:** бесплатный хостинг
[Streamlit Community Cloud](https://streamlit.io/cloud) выкладывает
приложение прямо из GitHub-репозитория.

### Необязательно, но полезно: ключ NCBI API

Без ключа NCBI разрешает ~3 запроса в секунду, с бесплатным ключом — до 10
(массовая обработка идёт заметно бодрее). Получить: ncbi.nlm.nih.gov →
регистрация → Settings → API Key Management → Create an API Key.

Ключ кладётся в файл `.streamlit/secrets.toml` (его нет в репозитории,
есть шаблон `.streamlit/secrets.toml.example`):

```toml
[ncbi]
api_key = "твой_ключ"
```

Если файла нет — всё работает как раньше, просто медленнее: программа
сама соблюдает паузы между запросами к NCBI.

### Консольная версия

Ядро (`prototype_semifinale.py`) можно запустить и без браузера
(нужен только Python 3 и `requests`):

```bash
python3 prototype_semifinale.py insulin
```

В папке появятся `card_<запрос>.txt` (для человека) и `card_<запрос>.json`
(машиночитаемый — его можно передать дальше в другую программу; это и есть
суть «связывающего слоя»). Консольная версия работает в автоматическом
режиме — берёт запись с наивысшим приоритетом, чтобы бенчмарк
повторялся с одинаковым результатом.

## Проверка точности: бенчмарк

`benchmark.py` — исследовательская часть проекта. Эталонный набор из
52 известных белков и их правильных UniProt-кодов; перед тестом каждый
эталон проверяется живым запросом к UniProt. Для каждого запроса
вызывается настоящая функция поиска ядра — бенчмарк не подменяет логику.
Считаются полнота, точность и **калибровка уверенности**: действительно ли
«ВЫСОКАЯ» ошибается реже, чем «НИЗКАЯ».

Результаты прогона на актуальном ядре (`prototype_semifinale`, сентябрь 2026):

| Метрика | Значение |
|---|---|
| Эталонов | 50 (2 отброшены при живой проверке) |
| Найдено | 50/50 = 100% |
| Точное попадание | 38/50 = 76% |
| Верное семейство генов | 4/50 = 8% |
| Ошибки | 8/50 = 16% |
| Калибровка «высокой» уверенности | 28/29 = **97%** |
| Калибровка «средней» | 5/7 = 71% |
| Калибровка «низкой» | 9/14 = 64% |

Главная метрика — калибровка: когда программа говорит «ВЫСОКАЯ», она
права в 97% случаев (28 из 29 «высоких» на эталонной выборке), а уровень
ошибки растёт ровно там, где программа
честно предупреждает о слабом сопоставлении. Повторить прогон:
`python3 benchmark.py` (нужен интернет, ~2–3 минуты).

## Честная оговорка (важно для защиты проекта)

Это **не** предсказательная ИИ-система. Программа ничего не предсказывает и
не «понимает» биологию — она находит и склеивает уже существующие записи
из трёх баз по одному и тому же названию гена/белка. Полноценная
ИИ-система, предсказывающая результат в живой клетке по дизайну гена, —
отдельная, гораздо более сложная задача. Чтобы обучить такую систему,
сначала нужно накапливать данные в едином формате — связывающий слой
вроде этого прототипа и есть первый шаг к сбору таких данных.

## Известные ограничения (честно, для защиты)

Это прототип, а не готовый продукт. Открытые ограничения:

- **Нет связности между базами.** Программа не проверяет, что найденная
  3D-структура в PDB относится именно к той изоформе белка, которую нашёл
  UniProt (берёт ID структур из ссылок UniProt как есть).
- **Нет семантической нормализации.** Описание функции из UniProt и
  описание гена из NCBI — два текста рядом, программа их не сравнивает.
- **Нет версионирования данных.** Карточка — снимок на момент запуска;
  если завтра в UniProt поменяют запись, старая карточка этого не покажет.
- **Массовый режим использует приоритеты, а не гарантию.** При нескольких
  совпадениях берётся запись про человека с основным именем гена, спорные
  строки помечаются. Это документированная практика (см. Ensembl VEP
  `--pick`), но не железная гарантия — поэтому и существует колонка
  «примечание» и шкала уверенности.
- **Темп запросов в массовом режиме опирается на устройство ядра.**
  Отдельной паузы между карточками нет: пауза стоит внутри ядра перед
  каждым запросом к NCBI, а между двумя NCBI-запросами всегда вклинивается
  запрос к UniProt. Редкий отказ сервера (429) ядро повторяет с нарастающей
  паузой; совсем не удавшиеся строки помечаются «ошибка» в таблице.
- **Нет турбо-режима для очень больших списков.** Обработка идёт
  последовательными запросами (~3 сек на карточку); пакетный ID mapping
  для тысяч названий — в планах.

## Технические детали, которые пригодятся на защите

- **UniProt** — самый «дружелюбный» источник: один запрос возвращает все
  нужные поля, включая список структур PDB.
- **NCBI Gene** хранит гены только для организмов с аннотированным геномом.
  Для инсулина человека (INS) запись подробная, а для GFP (медуза
  *Aequorea victoria*) отдельной записи «ген» в NCBI Gene нет — это пробел
  в данных базы, не ошибка программы. Программа умеет обнаруживать такую
  ситуацию и переключаться на NCBI Protein, честно помечая «запасной
  вариант».
- **RCSB PDB** умеет отдавать данные пакетом (GraphQL), но прототип
  запрашивает структуры по одной; у популярных белков структур сотни
  (у инсулина — 382, у GFP — 654), поэтому показываются первые примеры.
- **3D-модель** рисует 3Dmol.js (тот же движок, что в обёртке stmol),
  файл структуры скачивается напрямую с `files.rcsb.org` и кэшируется.
- **API-ключ NCBI** не обязателен: без него программа соблюдает паузы
  ~0.4 с между запросами NCBI, с ключом — ~0.15 с. Ключ хранится в
  `.streamlit/secrets.toml`, которого нет в репозитории (шаблон прилагается).
- У части старых структур PDB (например, снятых методом ЯМР) нет поля
  «разрешение» — оно есть только у рентгеновских структур; программа
  пишет это честно, а не ставит прочерк.
